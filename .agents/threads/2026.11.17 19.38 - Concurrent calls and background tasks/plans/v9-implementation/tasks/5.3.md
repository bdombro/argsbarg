## Notes

- Explicitly loaded `AGENTS.md`, `README.md`, plan `rules.md`, `architecture.md`, `conventions.md`, and all four contract-named source/test files.
- `src/mcp/env.ts` reads `process.env` / `process.platform` directly (`bootstrapMcpEnv`), while `src/mcp/env.test.ts` mutates/restores selected globals and uses an executable fake shell. That is acceptable precedent for MCP process bootstrap, but not the cheapest config-path seam: test a module-local selector with injected `{ platform, env, home }` and a platform-selected `node:path` flavor. Keep the public call on real process values. A separate injected mkdir dependency is enough to prove the side effect contract without touching the host.
- `src/mcp/env.ts:applyShellEnv` demonstrates host-value precedence without fallback. Extend that policy to config paths: select exactly one base; an explicit override or selected platform source that is invalid fails clearly, and does not try another source. `src/test/integration/mcp.test.ts:workspaceClient` shows isolated `mkdtemp` fixtures, env snapshots, `realpath`, and `context.after` cleanup; `src/mcp/pack/cursor.test.ts:cursor plugin` independently uses `try/finally` cleanup for filesystem packaging tests.

| Case | Expected |
| --- | --- |
| override `/var/tmp/demo` on POSIX | accept |
| override `C:\Users\me\AppData` on win32 | accept |
| override `\\server\share\AppData` on win32 | accept |
| override missing, `.` or relative (`config/demo`) | reject clearly; do not `resolve()` it into an absolute path |
| override `C:demo` on win32 | reject (drive-relative) |
| override `\demo` on win32 | reject (rooted but not drive/UNC-qualified) |
| APPDATA `C:\Users\me\AppData\Roaming` | accept |
| APPDATA `\\server\share\AppData` | accept |
| APPDATA missing, empty, drive-relative or root-relative | reject clearly; no `HOME`, XDG or cwd fallback |
| XDG/macOS/home-selected default is invalid or missing | reject clearly per the selected platform; do not cross-platform fallback |
| `~/demo` override | reject as written; no shell expansion |

- Windows qualification must be stricter than `path.win32.isAbsolute` alone because that accepts root-relative `\demo`. Require a drive-rooted or UNC root (`win32.parse(value).root` longer than `\`, or an equivalent explicit check) and use `win32` semantics in synthetic win32 tests.
- Prefer clear `TypeError`/validation error before filesystem access for bad inputs. For `mkdir(path, { recursive: true })`, use one call only, then return the chosen path. Do not catch, retry, probe existence, synthesize a directory elsewhere, or wrap filesystem failures; assert the original rejection object/code is preserved unchanged.
- Cheapest isolated assertions: pure selector table cases; one async test with an injected mkdir spy asserting one call with the selected directory and `{ recursive: true }`; one synthetic selector failure proving mkdir was never called and no fallback env/home value was considered; one injected rejection sentinel proving strict identity (`assert.rejects(..., (error) => error === sentinel)` or equivalent) and the unchanged code/message. Keep all host-global mutation/restoration in the selector's test if synthetic dependency injection is unavailable; no integration/process test is needed for this helper.
- Checks run: read-only source and test inspection only. No tests/builds were run, per contract.
