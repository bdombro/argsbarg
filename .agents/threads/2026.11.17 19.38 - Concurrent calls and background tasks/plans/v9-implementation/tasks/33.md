### DP-23 accepted wire fixture

Use these canonical sanitized values; object-key order is immaterial except the deterministic `tools` array order and byte-stable JSON fixture snapshots.

#### Accepted request metadata

Every 2026 request, including `server/discover`, `tools/list` and `tools/call`, carries:

```json
{
  "io.modelcontextprotocol/protocolVersion": "2026-07-28",
  "io.modelcontextprotocol/clientCapabilities": {},
  "io.modelcontextprotocol/clientInfo": { "name": "fixture-client", "version": "1" },
  "progressToken": 7
}
```

`clientInfo` and `progressToken` are optional. `protocolVersion` and `clientCapabilities` are required. `clientCapabilities` is an object, empty when the caller declares none. Unknown metadata keys are tolerated by the loose request envelope.

Accepted string and integer request ids are echoed unchanged. A valid notification omits `id`, produces no response and does not invoke a tool. Null, boolean, object and array ids are invalid requests.

#### `server/discover`

```json
{
  "jsonrpc": "2.0",
  "id": "discover",
  "method": "server/discover",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": "discover",
  "result": {
    "resultType": "complete",
    "ttlMs": 3600000,
    "cacheScope": "public",
    "supportedVersions": ["2026-07-28"],
    "capabilities": { "tools": {} },
    "instructions": "Fixture instructions.",
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "fixture-app",
        "version": "1.0.0"
      }
    }
  }
}
```

`instructions` is optional. Capability members reflect only enabled MCP features; task 23's minimal fixture has `tools`. `serverInfo` is result metadata, not a top-level discovery field.

#### `tools/call`

Both omitted `arguments` and `{}` bind to an empty object. A canonical call and result are:

```json
{
  "jsonrpc": "2.0",
  "id": "call",
  "method": "tools/call",
  "params": {
    "name": "echo",
    "arguments": { "value": "hello" },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": "call",
  "result": {
    "resultType": "complete",
    "content": [{ "type": "text", "text": "hello" }],
    "structuredContent": { "value": "hello" },
    "isError": false,
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "fixture-app",
        "version": "1.0.0"
      }
    }
  }
}
```

`content` is required; `structuredContent` and `isError` are optional. `isError: true` remains a successful JSON-RPC result. `ttlMs` and `cacheScope` do not belong on `tools/call`. Task 23 encodes only `complete`; `input_required`, `task` and their extension capabilities belong to later owners.

#### Cache and result ownership

- Every result object carries `resultType`; JSON-RPC errors do not.
- `resultType` is `complete` for this slice.
- `server/discover` and `tools/list` are `CacheableResult` values: `ttlMs` is a non-negative safe integer and `cacheScope` is `public` or `private`.
- The fixed task-23 catalog policy is exactly `{ ttlMs: 3600000, cacheScope: "public" }` for both methods because their contents are process-stable and caller-independent. `protocol.ts` stamps these values; registry entries and annotations cannot override them.
- `tools/call` is not a `CacheableResult` method. Invalid or incomplete cache fields in a call result are protocol errors rather than silently repaired.
- `_meta["io.modelcontextprotocol/serverInfo"]` is attached to every encoded result by the protocol encoder unless already supplied by the server identity owner. It is never read from client request metadata.

#### Required negative vectors

- Invalid JSON: `-32700`, `"Parse error"`, `id: null`.
- Non-object/batch envelope, invalid `jsonrpc`, invalid method shape, bool/null/non-integer id, response-with-request fields: `-32600`, `"Invalid Request"`, usable id echoed otherwise `id: null`.
- `_meta: null`, missing `protocolVersion`, missing `clientCapabilities`, non-string protocol version, or non-object/array capabilities: `-32602`.
- Unsupported version `2025-11-25`:

```json
{
  "jsonrpc": "2.0",
  "id": "old",
  "error": {
    "code": -32022,
    "message": "Unsupported protocol version: 2025-11-25",
    "data": {
      "supported": ["2026-07-28"],
      "requested": "2025-11-25"
    }
  }
}
```

- `initialize` is a compatibility probe, not a served method; it gets `-32022` with `data.supported: ["2026-07-28"]` (no missing-metadata error takes precedence for this method).
- A later feature that declares a required client capability and receives none uses:

```json
{
  "jsonrpc": "2.0",
  "id": "capability",
  "error": {
    "code": -32021,
    "message": "Missing required client capabilities: elicitation",
    "data": {
      "requiredCapabilities": { "elicitation": { "form": {} } }
    }
  }
}
```

Task 23 has no method that emits `-32021`; it pins the codec fixture for dependent Tasks/elicitation owners without implementing them.
- Unknown method `ping` or `initialize` outside the explicit compatibility branch: `-32601`, `"Method not found"`.
- `tools/call` missing/non-string `name`, `arguments: null`, array/scalar arguments, unissued cursor, or an unknown tool: `-32602`. Lookup failure occurs before `invokeBound`.
- D2 invalid, denied and thrown outcomes are not protocol-schema errors. Encode them as MCP-native tool failures with a `complete` call result or stable protocol error according to task 23's established outcome mapping, without raw credentials, stacks or transport status.

**Rationale.** The primary 2026 codec makes `protocolVersion` + `clientCapabilities` the required request envelope, preserves string/integer ids, requires `resultType`, defines `CacheableResult` only for discover/list/read methods, fixes cache field types, and places `serverInfo` in result `_meta`. The accepted fixed-catalog experiment supplies the deterministic one-hour/public policy. This resolves wire placement without changing D2, adapter ownership or public API scope.

**Rejected.**
- Official SDK defaults of `ttlMs: 0, cacheScope: "private"` for omitted cache hints: rejected for argsbarg's process-stable discovery/catalog because it would discard a settled useful cache policy and make every call cache-neutral.
- Registry/tool annotations as cache metadata: rejected; 2026 cache data is result protocol metadata and can drift if attached per tool.
- Inferring 2026 fields from 8.x initialization or `tools.ts`: rejected because those are explicitly legacy prior art.
- Accepting older revisions, null ids, fabricated HTTP headers, or caller-dependent discovery: rejected by the accepted 2026-only, D2 and fixed-catalog contracts.
- Treating host support as protocol acceptance: rejected. Claude Code/OpenCode/Copilot/Cursor/VS Code and real client behavior remain release verification gaps.
