### Decisions and alternatives

- Established:
  - D2: adapters alone bind and encode; `invokeBound` alone validates, runs guards and invokes the handler.
  - D2: a REST binder is collision-safe, creates no precedence rule, and combines all validated fields into flat `ctx.inputs`.
  - D2/DP-11: the HTTP base has `source: "http"`, `headers: NameView`, one `AbortSignal`, fresh locals and surface `"http"`; source views are exclusive.
  - Seed §7.4/§7.16: a returned Web `Response`, including a stream, is a legal HTTP-native result; `AppError` is encoded natively; disconnect ends the transport stream, not durable work.
  - Seed §7.5: REST dispatch and OpenAPI consume the same fixed registered catalog.
  - Task 24 owns listener streaming backpressure, disconnect cancellation, bind/rollback/drain and running-handle lifecycle.
- **`decided: DP-21` — declaration typing.** The optional root `http` block contains `guard?` and `routes`. `route<SeedLocals>()({...})` is the extracted identity builder; contextual structurally identical route literals are accepted inline. Methods are GET/POST/PUT/PATCH/DELETE; `path` is a leading-slash mount-relative `:identifier` template. Fields are `id`, `method`, `path`, required `description`, optional `tags`, `hidden`, `pathParams`, `queryParams`, `body`, `outputSchema`, `response`, `responses`, D2 `guard` and `handler`. `response` is `{ status?; headers? }`; each `responses` entry is `{ status; description; contentType?; schema?; headers? }`. `SeedLocals` is the locals present at operation-guard entry. Ordinary handlers carry `outputSchema` and return its output or `Response`; native-only handlers omit `outputSchema`, return `Response`, and require `responses` metadata. `id` is globally unique and is the OpenAPI operation ID. The public declaration never exposes `CompiledGuard`.
- **`decided: DP-21` — one-parse composite.** `pathParams`, `queryParams` and `body` accept only plain finite `ZodObject` roots. Registration rejects catchalls and object-level refinement/transform/pipe/default wrappers, then merges the disjoint `.shape` members into one `z.strictObject`. Field-level defaults/refinements/transforms remain intact and execute exactly once. Registration rejects duplicate output keys and path-schema mismatches before serving. The binder performs source-shape structural checks but never calls Zod; only `invokeBound.safeParse(rawInputs)` parses.
- **`decided: DP-21` — query wire.** Query names are case-sensitive and URL-decoded (`+` means space). Undeclared names and repeated scalar names fail 400 before invocation. Arrays are repeated names with one coerced item per occurrence; no comma syntax. String values preserve `""`; booleans accept exact `true`/`false`; numbers/integers accept finite JSON-number spellings; enum values remain text; objects consume one JSON text value and malformed JSON fails 400. Invalid scalar text remains raw for the shared Zod parse. Missing values are `undefined`. OpenAPI emits `style: "form"` and `explode: true`.
- **`decided: DP-21` — body framing.** Non-empty JSON input requires `application/json` or `application/*+json` with only an omitted/`utf-8` charset; otherwise return 415. Empty/whitespace-only input binds `{}`. A non-empty body must be a JSON object; malformed JSON, null, array and scalar roots return 400 before invocation. A body sent to a route without `body` returns 400. Schema-required body fields fail in `kind: "invalid"`, not in the wire parser.
- **`decided: DP-21` — outcomes and native responses.** The standard error body is `{ error: { code, message, details? } }`. Wire errors are 400 `INVALID_PATH`, `UNKNOWN_QUERY`, `REPEATED_QUERY`, `INVALID_QUERY_JSON`, `INVALID_JSON`, `INVALID_BODY` or `BODY_NOT_DECLARED`; unsupported/missing/wrong body media is 415 `UNSUPPORTED_MEDIA_TYPE`; no route is 404 `NOT_FOUND`. `invalid` is 400 `INVALID_INPUT` with details `{ issues: atMost10({ path, code, message }), issueCount }`; denial defaults to 403 while preserving `http.status/headers` and emits Bearer quoted `error`/space-joined `scope` challenge attributes; `AppError` uses `httpStatus ?? 500` plus stable fields and JSON-safe details; unknown/non-JSON success failures are generic 500 `INTERNAL_ERROR`; `undefined` is 500 `NO_RESULT`. CORS/trace finishing happens after encoding and preserves status/headers/body while overriding only framework-owned CORS/trace fields. The encoder returns a handler `Response` by reference without clone/read/buffer. Ordinary values are JSON; `response.status` overrides method defaults (GET 200, POST 201, PUT/PATCH 200, DELETE 200 with a value). A 204, binary, download or streamed response must be a native `Response`.
- **`decided: DP-21` — discovery identity.** Declaration `path` is mount-relative and excludes `/api`. Dispatch matches after the fixed mount; OpenAPI prepends `/api`. REST publishes only `/api/openapi.json` and `/api/docs`. `id` is `operationId`; explicit tags win, otherwise the first literal segment is the tag. `hidden` omits a still-callable route. `responses` documents native outcomes; `outputSchema`, default/declared success status and JSON media document ordinary results. Dispatch and OpenAPI use one frozen catalog.
- Alternatives:
  - Keep argv conversion: rejected by D2 because it conflates native sources and hides collisions.
  - Merge sources by precedence: rejected by the seed because path/body/query overlap must never be resolved by winner selection.
  - Keep deriving REST from CLI commands: rejected because independent declarations are the next-major public model.
  - Parse/validate separately in the HTTP server: rejected because it bypasses D2's one validation/guard/handler boundary; the composite schema belongs to registration.

### Behavior contract

- Registration: declarations, dispatch lookup and OpenAPI are one catalog snapshot. Hidden/discoverability behavior is declaration metadata, not a per-call guard.
- Catalog: route declaration, matching and OpenAPI use one frozen registration snapshot. Static/parameter overlap fails startup; runtime matching never resolves ambiguity by insertion order.
- Binding: path/query/body names are disjoint by construction. The binder never supplies a path key from query or body and never forwards one wire source as another.
- Raw-to-typed boundary: exactly one `invokeBound` call follows a successful bind. The runner performs the only schema validation and compiled guard execution; parsed defaults/transforms are visible to every guard and the handler.
- Headers: `headers.get` is case-insensitive and returns only request headers. HTTP has no `env` property and performs no process-env fallback, including local mirror misses.
- Cancellation: `request.signal` is the exact context/scope signal; adapter code does not race or recreate it.
- Success: `encode.ts` preserves native `Response` identity and body; ordinary result encoding must not consume a stream or reinterpret a handler `Response`.
- Failure: parser/binder failures use the accepted 400/415/404 codes before guard/handler; `invalid` is 400; denial keeps structured HTTP metadata; `AppError` uses stable code/status/details; unknown failures are generic 500. Later guards and handlers never run after denial/invalid.
- Discovery: every callable registered route appears in OpenAPI unless explicitly `hidden`; route IDs/tags and native/ordinary responses follow DP-21 and no inferred cross-generated endpoint appears.
- Lifecycle: this task neither binds nor closes a server, socket or job. It returns a `Response` for the listener owner.

### Failure and lifecycle contract

- Startup/registration is fail-closed: reject all collision/conflict conditions before publishing a catalog, rather than sorting and choosing a winner.
- A partial request parse failure returns no route side effects and no partially initialized invocation context.
- A response stream is not buffered by this slice. Cancellation/disconnect is observed by task 24 through the native Request/Response bodies; the binder merely retains the request signal.
- HTTP hooks/logging may observe status/error metadata, but the encoder remains the sole writer of the client response. Never log raw auth headers, source values, denial challenges or response bodies.
- Removing legacy REST argv code must be atomic with the explicit catalog handoff: no interval where dispatch validates one declaration while OpenAPI describes another.
