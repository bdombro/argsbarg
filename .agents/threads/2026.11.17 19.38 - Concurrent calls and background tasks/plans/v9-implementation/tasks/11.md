### Decisions and alternatives

- Established by D2:
  - Native binders identify a declaration and pass raw values; `invokeBound` is the shared runner. Adapters own all wire parsing/encoding.
  - `src/core/invocation.ts` owns `NameView`, `InvocationSource`, `Surface`, `InvocationBase`, `InvocationContext`, `Denial`, `GuardResult`, `Guard`, `OperationGuard`, opaque `CompiledGuard`, `BoundDeclaration`, `InvocationOutcome`, `allow`, `deny` and source-view behavior.
  - `src/core/errors.ts` owns `AppError(message, { code, httpStatus?, details?, cause? })` with `code`, optional `httpStatus` and `details`.
  - `src/runtime/invoke.ts` owns `compileGuardPlan` and `invokeBound`; `src/runtime/invocation-scope.ts` owns ALS/process output and captures invocation metadata and the signal.
  - Guard order is transport/mount seed, then surface default, then operation supplement/override/public replacement. The operation cannot bypass transport/mount checks. A new shallow locals object is used per call and guard additions merge in order.
  - Outcome is exactly `ok`, `denied`, `invalid` or `error`, each with captured stdout/stderr; raw `Response` is not a shared outcome. Invalid input and denied access never call later guards or the handler.
- Proposed:
  - Keep `invokeBound` intentionally independent of current `App`, `CommandContext`, hook pipeline and headless encoders. The new core can be tested directly; later factory/adapter work may bridge or replace old paths.
  - Extend the existing `src/runtime/invoke.test.ts` rather than add parallel fixture scaffolding; it already proves ALS overlap, hook order and invoke failure behavior. Add direct `invokeBound` fixtures in that file and keep current `App.invoke` assertions as regression coverage. The file name is broad enough for both runners; a separate test file would duplicate scope setup without isolating a distinct responsibility.
- Alternatives: defining a per-surface runner, reusing argv conversion, or using a generic `Response` were rejected by D2. No alternative is open in this brief.
- Assumptions:
  - A never-aborted signal is adapter-owned for entries with no native cancellation; the core receives and exposes only an `AbortSignal`.
  - Guards cooperate with cancellation through the supplied signal. The core cannot interrupt synchronous code or a handler that ignores it.

### Behavior contract

- Input: an exact D2 `BoundDeclaration`, opaque compiled guard plan, unknown `rawInputs`, and `InvocationBase`.
- Validation: exactly one schema parse. Parsed output, including transforms/defaults, is what guards and the handler receive. Invalid means `kind: "invalid"` with the same `ZodError`; it is not a generic `error`.
- Guards: serial async/sync callbacks in compile order. `true` continues, `false` yields `{ code: "DENIED", message: "Access denied" }`, `allow` shallow-merges, and `deny` carries D2 denial metadata. No handler or later guard runs after denial.
- Caller identity: supplied only through the fresh ordered locals seed/guard additions. No global caller, ambient process env lookup in HTTP mode, or hidden handler data.
- Handler: one call with the same `InvocationContext` object seen by guards. Its result is preserved as `result`; the runner does not call `ctx.respond()` or encode.
- Output: stdout/stderr are strings from the one ALS scope and present on all four outcomes. Raw credentials and source values are never added to outcomes.
- Error: every thrown unknown value is preserved under `error`; `AppError` is not flattened. Denial and invalid input are distinct outcomes.
- Cancellation: `AbortSignal` is required and context-visible. Aborted-before-start and cooperative abort throws return `kind: "error"`; no forced timeout/promise race is introduced.
- Locals evolution is represented in types, not by a mutable global or broad assertion. The final handler context is the strongest type established by the accepted compiled guard plan; missing required locals and accidental `any`/`unknown` widening must fail strict typecheck.
- Scope: the runner supplies invocation metadata and the captured signal through `runInInvocationScope`; handler business data remains on `InvocationContext`, not hidden in ALS. Adding a required scope field is a version-compatibility change and must be judged by DP-11 against the shared global symbol.

### Failure and lifecycle contract

- `safeParse` failure (including a throwing transform as `error`), guard denial, thrown guard, thrown handler and pre-aborted signal all close the ALS scope in `finally`.
- The scope closer must not invent a second outcome. The runner owns outcome construction and scope closure; unexpected failures from scope setup itself remain `error` only if captured by the runner.
- Async work scheduled by a handler retains ALS ancestry, but writes after settlement must follow the existing outside-scope route because `closed` is true.
- `process.exit` inside a core invocation continues to throw through the invocation scope rather than terminate; `invokeBound` classifies that thrown error as `error` unless the existing scope exit translation is explicitly supplied by a later adapter.
- Unknown errors remain inspectable by encoders. Core must not log raw errors, credentials, headers or handler data.

### DP-11: settle only the internal guard compiler/helper signatures

**Question:** D2 names `compileGuardPlan`, `allow` and `deny`, but does not give their complete parameter/generic signatures or the exact `InvocationScope` metadata field shape. What internal shapes let the D2 types compile the established surface-default plus `OperationGuard` plan while preserving generic locals evolution and remaining package-internal?

**Decision (`decided: DP-11`).** Use a curried compiler factory whose outer call supplies the package-internal validated input and transport seed types, while its returned overload set infers each guard's added locals:

```ts
type AddedLocals<G> = G extends (
  ...args: never[]
) => infer R
  ? Awaited<R> extends GuardResult<infer Added>
    ? Added
    : never
  : never;

type MergeLocals<L extends object, R extends object> = {
  [K in keyof L | keyof R]:
    K extends keyof R ? R[K] : K extends keyof L ? L[K] : never;
};
type SafeAddedLocals<G> =
  IsAny<AddedLocals<G>> extends true ? never : unknown;

declare const compiledGuard: unique symbol;
interface CompiledGuard<Input, Seed extends object, Final extends object> {
  readonly [compiledGuard]: {
    readonly input: (value: Input) => Input;
    readonly seed: (value: Seed) => Seed;
    readonly final: (value: Final) => Final;
  };
}

interface GuardCompiler<Input, Seed extends object> {
  <
    SurfaceGuard extends Guard<Input, Seed, object>,
    OverrideGuard extends Guard<Input, Seed, object>,
  >(
    guards: {
      readonly surface?: SurfaceGuard & SafeAddedLocals<SurfaceGuard>;
      readonly operation: {
        readonly mode: "override";
        readonly run: OverrideGuard & SafeAddedLocals<OverrideGuard>;
      };
    },
  ): CompiledGuard<
    Input,
    Seed,
    MergeLocals<Seed, AddedLocals<OverrideGuard>>
  >;
  <SurfaceGuard extends Guard<Input, Seed, object>>(
    guards: {
      readonly surface?: SurfaceGuard & SafeAddedLocals<SurfaceGuard>;
      readonly operation: "public";
    },
  ): CompiledGuard<Input, Seed, Seed>;
  <
    SurfaceGuard extends Guard<
      Input,
      Seed,
      object
    > = Guard<Input, Seed, Record<never, never>>,
    OperationGuard extends Guard<
      Input,
      MergeLocals<Seed, AddedLocals<SurfaceGuard>>,
      object
    > = Guard<
      Input,
      MergeLocals<Seed, AddedLocals<SurfaceGuard>>,
      Record<never, never>
    >,
  >(
    guards: {
      readonly surface?: SurfaceGuard & SafeAddedLocals<SurfaceGuard>;
      readonly operation?: OperationGuard & SafeAddedLocals<OperationGuard>;
    },
  ): CompiledGuard<
    Input,
    Seed,
    MergeLocals<
      MergeLocals<Seed, AddedLocals<SurfaceGuard>>,
      AddedLocals<OperationGuard>
    >
  >;
}

declare function compileGuardPlan<Input, Seed extends object>():
  GuardCompiler<Input, Seed>;
```

`compileGuardPlan<Input, Seed>()` returns this package-internal callable overload object; the outer call is supplied by registration, not authored by consumers. `SurfaceGuard`, `OperationGuard` and `OverrideGuard` are constrained to the exact D2 `Guard` parameter types (`Seed` for the surface and override; `MergeLocals<Seed, AddedLocals<SurfaceGuard>>` for the supplement). `allow` is overloaded as `allow(): { kind: "allow" }` and `allow<const Added extends object>(locals: Added): { kind: "allow"; locals: Added }`; `deny(denial: Denial)` returns `{ kind: "deny"; denial }`. The package-internal `bind`/declaration boundary checks `Parameters<Handler>[0]` and rejects `any` or `unknown`; its expected context is exactly `InvocationContext<Input, Final>`.

`InvocationScope` metadata is exactly:

```ts
readonly metadata: {
  readonly source: "local" | "http";
  readonly surface: Surface;
};
readonly signal: AbortSignal;
```

These fields are scoped invocation metadata, not handler data: the scope does not contain inputs, locals, caller, env or headers. The captured `signal` retains the `InvocationBase` signal by reference. They make the scope shape version-incompatible with v1, so `INVOCATION_SCOPE_VERSION` becomes `2`.

2. a surface guard adding `caller`;

**Decision acceptance (`decided: DP-11`):** the selected generic stays package-internal and cannot silently accept `any` guard additions or `any`/`unknown` handler contexts.
