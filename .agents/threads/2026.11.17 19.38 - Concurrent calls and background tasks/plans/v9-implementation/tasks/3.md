## Brief

Independently refined from local source, test and package evidence after **decided: D3**. The API and failure policy are settled; the brief has no remaining consequential implementation choices.

### Why and current state

Give an app one stable, per-user config directory across installs, independent of how it runs. The settled [seed §7.25](../../2026.11.18%20-%20Argsbarg%20next%20major%20design%20decisions.md#725-app-config-directory-helper) requires an opt-in helper: an app-provided absolute override wins; otherwise choose the native XDG/macOS/Roaming AppData location; create the resolved directory only when called. The 8.x [settings guide](../../../../../../docs/use-cases/settings.md), [CLI guide](../../../../../../docs/cli-program.md#app-settings) and `docs/developing.md` consistently keep file names, loading, schemas, saving and storage in app code. `package.json` exposes one root export and `src/index.ts` is the only package entrypoint; the 8.x helper exports named in `docs/developing.md` are removed and must not be restored.

### Established behavior and decided API

- **Established, seed + architecture:** Resolve one absolute app directory. `override` is the complete app directory, not a base. An app selects and passes its own override; the helper does not discover env vars, workspaces, install locations or existing config. On Linux use absolute `XDG_CONFIG_HOME/<appKey>` or `homedir()/.config/<appKey>`; macOS uses `homedir()/Library/Application Support/<appKey>`; Windows uses absolute `APPDATA/<appKey>`. Normalize lexically. Call `mkdir(directory, { recursive: true })` exactly when the helper is called; do not add a `stat`/existence probe, startup lifecycle hook or child-mount behavior.
- **Established, package:** Runtime code belongs under `src/`; direct public consumption is from `"argsbarg"` only. `package.json` has Zod as its only peer and no production dependencies, and `src/index.ts` owns explicit public exports.
- **Public API — decided: D3:** Export `resolveConfigDir(appKey: string, override?: string): Promise<string>` from the package root during the later public handoff. The implementation lives in `src/core/config-dir.ts`, with `src/core/config-dir.test.ts`; no package subpath is added. `undefined` means no override, while an explicitly supplied empty string is invalid.
- **Internal test seam — decided: D3:** The config leaf module exports a package-private pure `selectConfigDir({ appKey, override, platform, env, home }): string` for its colocated test. Here, package-private means importable from the module's `.ts` path by repository code but unavailable through the package's sole `"argsbarg"` export; `selectConfigDir` is never re-exported from `src/index.ts`. The real call samples `process.platform`, `process.env` and `homedir()` at call time. Use real temp directories for filesystem behavior rather than a general-purpose dependency-injection layer.
- **App key rule — decided: D3:** Because `core/types.ts` only documents `CommandBase.key` and `core/validate.ts`/`cli-tool/create.ts` provide no reusable root-key validator, accept only the single ASCII segment `^[A-Za-z0-9][A-Za-z0-9._-]*$`; reject `.`, `..`, path separators and NUL. Do not sanitize, trim or rewrite the caller's identity.
- **Platform defaults and rejection — decided: D3:** Missing or invalid Windows `APPDATA` is an `InputError`; require a drive-rooted or UNC-rooted path and never infer from `home`, XDG or cwd. Unsupported `process.platform` values are also an `InputError`, not a POSIX assumption or alternate location.

### Recipe and failure behavior

1. Add `src/core/config-dir.ts` and `src/core/config-dir.test.ts`; do not edit `src/index.ts` in this task. The leaf follows `src/server/overrides.ts`: import Node dependencies at the top, keep a small resolver and wrapper, use an explicit `string` result, and provide the required purpose header plus human-readable JSDoc for every new symbol/property. Sort imports by module source (`node:fs/promises`, `node:os`, `node:path`, then `./leaf-inputs.ts`) and use `InputError` from `./leaf-inputs.ts`; add no production dependency.
2. Add the D3 `selectConfigDir` pure seam and public async wrapper (**decided: D3**). The seam's inline options object contains `appKey: string`, `override?: string`, `platform: NodeJS.Platform`, `env: NodeJS.ProcessEnv` and `home: string`; expose only this function from the leaf module and `resolveConfigDir` as the eventual root handoff. Validate `appKey` first. Use `node:path.posix` for Linux/macOS and `node:path.win32` for Windows; tests must therefore produce the same result regardless of the host OS. Normalize the selected absolute directory. Do not trim values, expand `~`/variables, sanitize identity, or call `resolve(cwd, value)`.
3. If `override !== undefined`, validate and normalize that complete directory without consulting a default branch. For POSIX platforms require `path.posix.isAbsolute`; for Windows require `path.win32.isAbsolute` plus a drive-rooted or UNC root (a bare `\` root is invalid). Reject empty/whitespace-only, NUL-containing, relative, drive-relative (`C:demo`) and Windows root-relative (`\demo`) values according to the selected platform. Throw `InputError` with `Invalid config directory override: expected an absolute path.` and never echo the supplied value or fall back (**decided: D3**).
4. Without an override, on Linux use a non-empty, NUL-free, POSIX-absolute `XDG_CONFIG_HOME`; treat absent, empty, NUL-containing or relative XDG as unset and use a POSIX-absolute `homedir()/.config`. On macOS use POSIX-absolute `homedir()/Library/Application Support` and ignore XDG. On Windows require NUL-free `APPDATA` with a fully qualified drive or UNC root, otherwise throw `InputError` with `Invalid APPDATA: expected an absolute drive-rooted or UNC path.` Treat NUL-containing or relative selected home as invalid. Throw `InputError` with `Invalid home directory: expected an absolute path.` when the selected Linux/macOS default needs an invalid home, and `Unsupported platform: config directory defaults are unavailable.` for any other platform. Never invent a cwd-relative, cross-platform or alternate location (**decided: D3**). The async wrapper samples process values at call time, not module import, while the selector performs all precedence and failure decisions.
5. Invalid `appKey` values throw `InputError` with `Invalid app key: expected a single safe path segment.` before override/default validation (**decided: D3**). Await exactly one `mkdir(directory, { recursive: true })`, then return the normalized path. An existing directory succeeds; an existing file rejects. Filesystem errors propagate unchanged by identity/code/message: no wrapping, retry, fallback, cleanup, logging or `stat` pre-check. Do not delete parents after a partial failure.
