## Notes

- **Outcome:** **decided: D3**. Accept `resolveConfigDir(appKey: string, override?: string): Promise<string>` as the eventual package-root API. Keep selection pure and platform-testable through a module-exported `selectConfigDir({ appKey, override, platform, env, home }): string` that is not re-exported from `src/index.ts`. Keep filesystem creation in the wrapper with real-directory tests.
- **D3 key/path policy:** Accept one ASCII segment matching `^[A-Za-z0-9][A-Za-z0-9._-]*$` and reject `.`, `..`, separators and NUL without trimming or sanitizing. An override is the complete directory. Missing or invalid Windows `APPDATA`, invalid selected home and unsupported platforms fail closed. Windows APPDATA must be drive-rooted or UNC-rooted; it never falls back to home, XDG or cwd.
- **D3 failure contract:** Validation/default/platform failures reject as `InputError` with fixed, field-specific messages that do not echo supplied values: invalid app key, invalid override, invalid APPDATA, invalid home, or unsupported platform. Invalid key wins first; valid explicit override wins before default inputs are read. Filesystem errors from the single recursive `mkdir` reject unchanged by identity/code/message; no probe, wrapping, retry or fallback.
- **Rejected alternatives:** A sync API, options-object public signature, subpath export, public platform selector, global-platform/env mutation for tests, injectable filesystem abstraction, path sanitization, relative-path rebasing, APPDATA fallback to home, unsupported-platform POSIX treatment, fallback after bad override, and config loading/storage/discovery were rejected. They add public surface, test machinery, ambiguous identity or silent path changes without improving the leaf.
- **Affected Brief updates:** Task 3's public API, internal seam, app-key, Windows/platform, recipe and verification/graph lines now carry `decided: D3`. Exact error messages and assertions are deterministic; task 3's contracts and Notes were not edited.
- **Remaining graph impact:** No source, map or plan contract changes. The leaf implementation remains independent. A later public-root handoff must export only `resolveConfigDir`; docs and Unreleased changelog follow the accepted leaf, and no examples/template sync is required. Independent task-3 refinement remains required before implementation.
