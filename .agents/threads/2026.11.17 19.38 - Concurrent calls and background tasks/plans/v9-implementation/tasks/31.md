### DP-21 exact outcome

1. **Declaration typing.** `http` is an independent optional block with `guard?` and `routes`. A route is either a contextual object literal or the result of the curried identity builder `route<SeedLocals>()`. Its method is `GET | POST | PUT | PATCH | DELETE`; path is one leading-slash mount-relative template with `:identifier` placeholders. Fields are `id`, `method`, `path`, required `description`, optional `tags`, `hidden`, `pathParams`, `queryParams`, `body`, `outputSchema`, `response`, `responses`, `guard` and `handler`. `response` is `{ status?: number; headers?: Readonly<Record<string, string>> }`; each `responses` entry is `{ status: number; description: string; contentType?: string; schema?: z.ZodType; headers?: readonly string[] }`. `SeedLocals` is the locals present at operation-guard entry; supplement infers additions, override starts from transport seed, and `"public"` uses exactly that seed. Ordinary result typing requires `outputSchema`; native-only routes omit it and require `responses` metadata. IDs are globally unique OpenAPI operation IDs. The builder never exposes `CompiledGuard`.
2. **Composite schema.** Each present path/query/body field accepts a plain `ZodObject`, with a finite explicit shape and no catchall. Registration merges their `.shape` members into one `z.strictObject` and rejects any cross-source key overlap, path-placeholder/schema mismatch, missing/non-string path field, or object-level refinement/transform/pipe/default. Field-level optional/default/refinement/transform behavior is preserved. `invokeBound` performs the sole `safeParse`; binder source checks never call Zod.
3. **Query.** Names are exact and case-sensitive. Decode with URL semantics (`+` is space). Reject undeclared names and repeated scalar names before invocation. Array parameters use repeated names and one coerced item per occurrence; never comma-split. Strings keep empty text. Booleans accept only exact `true`/`false`; integers/numbers accept finite JSON-number spellings; enum scalars remain text. Objects consume exactly one JSON text value; malformed object JSON is a 400 binder failure. Invalid scalar text remains raw so the one Zod parse reports `INVALID_INPUT`. Missing is `undefined`; an explicitly empty scalar is `""`. OpenAPI uses `style: "form"` and `explode: true`.
4. **JSON body.** A non-empty body requires `Content-Type: application/json` or `application/*+json`, with only an omitted or `utf-8` charset parameter; otherwise return 415. Empty/whitespace-only content binds as `{}`. Non-empty JSON must decode to a non-null, non-array object; malformed JSON, null, arrays and scalars return 400 before invocation. A body sent to a route with no `body` declaration returns 400. Required body fields fail in the shared Zod parse, not the binder.
5. **Outcomes and `Response`.** All framework errors use `{ error: { code, message, details? } }`. Wire errors are 400 `INVALID_PATH`, `UNKNOWN_QUERY`, `REPEATED_QUERY`, `INVALID_QUERY_JSON`, `INVALID_JSON`, `INVALID_BODY` or `BODY_NOT_DECLARED`; unsupported/missing/wrong body media is 415 `UNSUPPORTED_MEDIA_TYPE`; no route is 404 `NOT_FOUND`. `invalid` is 400 `INVALID_INPUT` with details `{ issues: atMost10({ path, code, message }), issueCount }`. Denial uses `denial.http.status ?? 403`, keeps code/message and emits `WWW-Authenticate: Bearer` with quoted `error`/space-joined `scope` attributes when supplied. `AppError` uses `httpStatus ?? 500` and stable code/message plus details only when JSON-safe. Unknown errors and non-JSON success serialization are generic 500 `INTERNAL_ERROR`; `undefined` is 500 `NO_RESULT`. CORS/trace composition happens after encoding, preserves handler status/headers/body (including `set-cookie`) and overrides only framework-owned CORS/trace fields. The REST encoder returns a handler `Response` by reference without cloning, reading or buffering it. Ordinary values are JSON with `application/json; charset=utf-8`; `response.status` precedes method defaults (GET 200, POST 201, PUT/PATCH 200, DELETE 200 with a value). A 204 and all non-JSON/binary/stream forms require native `Response`.
6. **Discovery.** Route `path` is mount-relative and begins `/` without `/api`; the catalog matcher sees the path after the fixed `/api` mount. OpenAPI keys prepend `/api`; REST discovery is `/api/openapi.json` and `/api/docs`. `id` becomes `operationId`; explicit tags win, otherwise the first literal segment is the tag. Hidden routes remain callable but are omitted. Native responses are described by required `responses` metadata; ordinary output uses `outputSchema`, `response.status` and generated JSON metadata. Dispatch and OpenAPI consume one frozen route snapshot.

**Serialization fixtures.**

- `POST /api/projects/alpha/reports?dryRun=true&tag=short&tag=pdf` plus body `{"format":"pdf"}` binds `{ id: "alpha", dryRun: true, tag: ["short", "pdf"], format: "pdf" }`; the sole Zod parse applies any defaults/transforms to that object.
- `?dryRun=` remains `dryRun: ""` and fails boolean schema input; `?tag=` is `[""]`; `?dryRun=true&dryRun=false` is a 400 binder error.
- Empty JSON framing binds `{}`; malformed JSON/null/array/scalar is 400; valid JSON under a non-JSON media type is 415; required body fields fail as 400 `INVALID_INPUT`.
- Native `Response` returns by identity from `encode.ts`; ordinary `{ ok: true }` becomes a JSON 201 for POST; returned `undefined` becomes 500 `NO_RESULT`.
