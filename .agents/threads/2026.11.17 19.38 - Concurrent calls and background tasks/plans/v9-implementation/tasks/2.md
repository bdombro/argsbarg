### D2: decide one native-binding invocation seam

**Decision.** `decided: D2`. Keep `argsbarg(spec)` and the independent declarations. Do not add a mandatory operation object. Native binders convert only the selected declaration's wire-local values; one runner validates `rawInputs`, runs an ordered guard pipeline, invokes the handler, and returns an outcome. No binder, runner, hook, or handler writes a wire response. Adapters alone encode outcomes, including streams and protocol challenges.

**Exact ownership and filenames.**

1. `src/core/invocation.ts` owns public/internal structural contracts below plus `allow`, `deny`, and the source view. `src/core/errors.ts` owns `AppError`.
2. `src/runtime/invoke.ts` owns `compileGuardPlan`, `bind...`-independent validation/guard/handler orchestration, and `invokeBound`. It must not import a concrete CLI, REST, JSON-RPC, or MCP adapter.
3. `src/runtime/invocation-scope.ts` remains the ALS/process-output owner. Extend its scope with the invocation metadata and captured signal; `invokeBound` is always entered through `runInInvocationScope`. Guards and handlers receive the same context object directly; ALS is for process-output/protocol isolation, not hidden handler data.
4. The three edge families implement, never redefine, the contracts: CLI/local mirrors in `src/cli/bind.ts` and `src/cli/encode.ts`; REST and JSON-RPC together in `src/http/bind.ts` and `src/http/encode.ts` (`src/json-rpc/bind.ts` may specialize envelopes); MCP stdio/HTTP in `src/mcp/bind.ts`, `src/mcp/dispatcher.ts`, and their two transport adapters. This is source placement, not a public subpath/package.
5. Factory-side registration in `argsbarg(...)` resolves each declaration to one `BoundDeclaration` and rejects duplicate source-to-input keys before serving. It owns startup lookup/discovery; `invokeBound` does not inspect argv, `Request`, JSON-RPC, or MCP envelopes.

**Structural contract.**

```ts
type MaybePromise<T> = T | Promise<T>;

export interface NameView {
  get(name: string): string | undefined;
}

export type InvocationSource =
  | { readonly source: "local"; readonly env: NameView; readonly headers?: never }
  | { readonly source: "http"; readonly headers: NameView; readonly env?: never };

export type Surface = "cli" | "http" | "jsonRpc" | "mcp";

export type InvocationBase<Locals extends object> = {
  readonly locals: Locals;
  readonly signal: AbortSignal;
  readonly surface: Surface;
} & InvocationSource;

export type InvocationContext<Input, Locals extends object> =
  InvocationBase<Locals> & { readonly inputs: Input };

export type Denial = {
  readonly code: string;
  readonly message: string;
  readonly http?: {
    readonly status?: number;
    readonly headers?: Readonly<Record<string, string>>;
  };
  readonly challenge?: {
    readonly scheme: "bearer";
    readonly error?: "invalid_token" | "insufficient_scope";
    readonly scopes?: readonly string[];
  };
};

export type GuardResult<Added extends object = Record<never, never>> =
  | boolean
  | { readonly kind: "allow"; readonly locals?: Added }
  | { readonly kind: "deny"; readonly denial: Denial };

export type Guard<Input, Current extends object, Added extends object = Record<never, never>> = (
  context: InvocationContext<Input, Current>,
) => MaybePromise<GuardResult<Added>>;

export type OperationGuard<G> = G | { readonly mode: "override"; readonly run: G } | "public";

declare const compiledGuard: unique symbol;
export interface CompiledGuard {
  readonly [compiledGuard]: "compiled";
}

export interface BoundDeclaration<InputSchema extends z.ZodType, Result, Locals extends object> {
  readonly inputSchema: InputSchema;
  readonly guardPlan: readonly CompiledGuard[];
  handler(context: InvocationContext<z.output<InputSchema>, Locals>): MaybePromise<Result>;
}

export type InvocationOutcome<Result> =
  | { readonly kind: "ok"; readonly result: Result; readonly stdout: string; readonly stderr: string }
  | { readonly kind: "denied"; readonly denial: Denial; readonly stdout: string; readonly stderr: string }
  | { readonly kind: "invalid"; readonly error: z.ZodError; readonly stdout: string; readonly stderr: string }
  | { readonly kind: "error"; readonly error: unknown; readonly stdout: string; readonly stderr: string };

export function invokeBound<InputSchema extends z.ZodType, Result, Locals extends object>(request: {
  declaration: BoundDeclaration<InputSchema, Result, Locals>;
  rawInputs: unknown;
  base: InvocationBase<Locals>;
}): Promise<InvocationOutcome<Result>>;
```

`CompiledGuard` is runtime-erased from a typed `Guard`; it receives validated `inputs` and a mutable-internally, read-only-to-callbacks locals object. `allow({ ... })` returns `kind: "allow"` and shallow-merges in order. `true` adds nothing; `false` produces `{ code: "DENIED", message: "Access denied" }`. A thrown guard follows the unexpected-error path and never reaches the handler. The runner constructs a fresh locals object per call.

**Type inference and extraction.** Inline `argsbarg({ ... })` types each surface's handler locals from that surface's default guard plus any operation supplement; `defineSurface`-style inference may be internal, not a required author layer. Extracted operations use `command<CliLocals>`, `route<HttpLocals>`, `method<JsonRpcLocals>`, and `tool<McpLocals>` identity builders. Each builder infers input/output from its Zod schemas and checks the handler's return type. No `CommandContext`/`any`, raw `unknown` handler context, or mandatory `operation()` wrapper is allowed. Use `NoInfer` where an array or storage target would otherwise choose a wider generic.

**Guard order and identity.**

1. A transport/mount middleware runs first and cannot be suppressed by an operation guard. `mcp.http.middleware`/OAuth may return `{ kind: "respond"; response: Response }` without dispatch, or `{ kind: "next"; locals }` that seeds the call.
2. The surface default guard runs next, including for local mirrors. If absent, locals begin with mount/adapter locals.
3. An operation `guard` supplements by default, runs after the surface guard, and sees merged locals. `guard: { mode: "override", run }` replaces only the surface guard; `guard: "public"` replaces it with none. Neither bypasses transport/mount checks.
4. On MCP `tasks/get`, `tasks/update`, and `tasks/cancel`, run the same MCP mount and surface plan with a freshly established caller before invoking the provider. The provider receives only its operation-specific inputs, `caller`/locals, and its request signal.
5. A handler declaration may require `locals.caller` only when the app's every enabled entry that reaches it establishes it. The builder types this from the composed guard locals; runtime guards still verify the credential.

**Errors and native outcomes.**

```ts
export class AppError extends Error {
  constructor(message: string, options: {
    code: string;
    httpStatus?: number;
    details?: unknown;
    cause?: unknown;
  });
  readonly code: string;
  readonly httpStatus?: number;
  readonly details?: unknown;
}
```

`AppError` is the one framework domain-error class. REST maps `httpStatus` plus stable `code/message/details`; RPC emits a protocol error carrying that stable code in data; MCP emits a tool error; CLI writes a diagnostic and exits nonzero. Unknown errors are logged as unexpected and encoded generically. `Denial` is not an `AppError`: CLI/MCP/RPC use code/message natively, while an HTTP encoder applies `http.status/headers` and `challenge`. The MCP OAuth helper completes guard evaluation before opening SSE, then adds `resource_metadata` to the bearer challenge. A raw `Response` is legal only as an HTTP route's handler result or an MCP HTTP middleware's pre-dispatch `respond`; it is not a shared guard return or common outcome.

**Scenario checks for implementers.**

- **CLI command:** the CLI binder creates `{ projectId: "alpha" }`; source is local; `env.get` is the only credential view; the runner validates and writes no stdout. CLI encoding emits returned/captured output and exits via return/exit code, not `process.exit` inside the shared runner.
- **Mixed-source REST route:** separate path/query/body declarations bind to one flat `rawInputs`. Registration rejects any repeated output key. An explicit `path: id`, query/body collision cannot overwrite `id`; the same flat object reaches guards and handler. A returned Web `Response` passes through the REST encoder, including stream/backpressure/disconnect behavior, and is never parsed into JSON or accepted by a tool/RPC declaration.
- **MCP tool over HTTP vs stdio/mirror:** one tool declaration and one dispatcher. HTTP mount middleware may seed `locals.caller`; stdio and local mirror use `source: "local"` and mcp/tool guards instead. A missing HTTP header never falls back to env. A task follow-up re-verifies its caller from the current transport and never reuses the original request credentials.
- **Mounted child:** the parent composes the child's declarations and guard plan without calling child `run()`. The child's `NameView` is a prefix-stripped mount view of the same source; child guards run; no sibling/unprefixed/env fallback. Public exposure, validation, and dispatch remain one registered catalog.

**Why this choice.** It absorbs the 8.x useful pieces (`command` schema inference, validated `ctx.inputs`, `InvokeResult`, and ALS output capture) while removing the current `httpRequestToArgv` / MCP `mcpToolCallToArgv` loop. A raw-input runner also makes mirrors use the declaration without fake argv, headers, or transport middleware.

**Rejected alternatives.**

- Keep converting REST/MCP to argv: rejected because it loses native source boundaries and needs precedence workarounds.
- A required `operation()` layer: rejected by 7.1 and the small-CLI constraint; ordinary business functions remain sharing points.
- One broad `App.invoke(argv | object)` union: rejected because it reopens argv/source ambiguity and weakens contextual types.
- A common `Response`/JSON envelope: rejected because streams, RPC errors, MCP task results, and CLI output need native encoders.
- Raw `Response` for every guard denial: rejected because stdio/CLI cannot encode it without inventing HTTP semantics; structured `Denial` carries only optional HTTP/challenge metadata.
- A single per-surface runner or mutable global caller: rejected because mount/guard ordering and parallel-call isolation can drift.

**Remaining decisions outside D2.** Exact listener/serve flags and running-handle fields; relay credential/display flags; final OAuth verifier/helper options; task provider payload schemas; and first-release URL elicitation eligibility remain elsewhere. Real harness/upstream support claims remain unverified. D2 supplies the typed caller, raw-input, denial, and outcome boundary those decisions must use.
