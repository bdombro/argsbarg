### Why and canonical context

- Rationale: the v9 surfaces need one selected process listener instead of each adapter binding a server, while preserving native `Request`/`Response` results and the existing app-owned invocation boundary.
- Context: seed §§7.4 and 7.16 require incremental Web streams, backpressure, disconnect handling and transport-owned native encoding; §§7.5, 7.7 and 7.19 require REST, JSON-RPC and MCP HTTP to share HTTP transport without sharing dispatch or middleware. §§7.10-7.11 and architecture rev 2 require one executable, no listener during import/CLI/stdio, collision rollback, owned-resource cleanup, drain on shutdown and a normally resolved `app.run()`.

### Decisions and alternatives

- Established:
  - D2/DP-11: adapters bind native inputs and seed `InvocationBase`; `invokeBound` returns transport-neutral outcomes. A listener may create the request signal and transport context, but must not invoke guards/handlers or encode their outcomes itself.
  - Seed 7.4: async calls overlap; each invocation has isolated output/caller/cancellation. Stream incrementally, honor backpressure, and treat disconnect as ending transport work rather than durable app-owned work.
  - Seed 7.5/7.7/7.19: REST `/api`, RPC `/rpc` and MCP `/mcp` are independent registered mounts on one HTTP server. MCP middleware is mount-local and absent from stdio/sibling mounts.
  - Seed 7.10/7.11 and architecture rev 2: no listener setup on import/help/CLI/stdio; one selected serve branch; failed bind rolls back partial startup; shutdown drains active calls and resolves `app.run()`; remove only a socket created by this runtime.
- Selected (`decided: DP-24`):
  - Put the protocol-neutral Web/Node bridge, mount dispatcher, bind acquisition and running handle in `src/server/listener.ts`; keep `src/server/context.ts` for mutable server state and `src/server/overrides.ts` for resolved author config. Listener code receives assembled mounts; it does not import REST, JSON-RPC or MCP and does not assemble their catalogs.
  - Use one package-internal `HttpMount` with flat `claims`; a claim is `{ kind: "exact" | "prefix", path }`, and one `handle(Request, context): MaybePromise<Response>` owns every path claimed by that mount. Exact and prefix paths are absolute, normalized and segment-oriented. Duplicate exact paths or any overlap at segment granularity (including nested/equal prefixes and an exact path inside a prefix) fail before binding; disjoint exact/prefix claims and method-specific behavior remain adapter-owned. Match exact before prefix only as defense in depth; accepted registration cannot depend on that order. One unhandled path returns the listener's generic 404 without trying another adapter.
  - The only mount context is `{ signal: AbortSignal }`. It is the exact controller signal attached to the Web `Request`; the listener neither seeds guards nor exposes Node streams, `ServerRuntime`, logger, bind socket or borrowed app resources. `Request.url` retains the complete absolute URL.
  - Use `{ kind: "tcp", host, port } | { kind: "unix", path }` as the normalized, package-internal `HttpListenTarget`. TCP accepts integer ports `0..65535`; Unix ships in the first slice with an absolute, normalized path and no parent-directory creation or permission policy. `ResolvedHttpServeConfig` becomes the sole migration boundary for resolved author configuration and exposes a non-empty `targets` array plus the existing HTTP/log settings; current host/port resolution emits one TCP target. No raw CLI/env/header target resolution belongs in the listener.
  - `startHttpListener({ mounts, targets }): Promise<HttpListenerHandle>` validates all claims/targets before opening a socket, then creates and binds endpoints serially behind one startup barrier. A successful handle exposes frozen `addresses`, one `terminal: Promise<void>`, a live `state` snapshot and `stop({ forceAfterMs? }): Promise<void>`. The first stop call fixes the policy and all later calls return the exact same terminal promise.
  - The default force deadline is `10_000ms`; `forceAfterMs` is a finite non-negative integer and is primarily injected for tests. `stop` is the one public lifecycle operation: it performs drain, then an internal force transition at the deadline. No separate `drain()` or `force()` method reaches adapters.
- Alternatives:
  - Keep `src/http/server.ts` as the networking owner: reject; it would force REST to own JSON-RPC/MCP listener lifecycle and recreate adapter coupling.
  - One generic middleware/router framework: reject; the small fixed mount set can be checked without another plugin system. The contract still needs exact prefix and exact-path claims so `/api`, `/rpc`, `/mcp` and shared root endpoints cannot overlap accidentally.
  - Buffer bodies in Web conversion: reject; it violates first-byte latency, memory bounds and the accepted streaming contract.
  - Immediate `process.exit` on signal: reject; it bypasses socket rollback, in-flight drain and user `app.run()` cleanup.
  - Always unlink a Unix socket during cleanup: reject; collision/startup failures can encounter a pre-existing foreign socket and must preserve it.
  - A broad ordered middleware chain: reject; D2 and the fixed mount set need one registered owner, not fallback middleware.
  - Independent `drain` and `force` calls from callers: reject; they make the same operation race and let callers choose incompatible terminal policies. One memoized `stop` owns both transitions.
- Assumptions:
  - Node's supported runtime (≥20 in README, ≥22.18 for development) can construct streaming `Request` bodies with `duplex: "half"` and can bridge Web streams to Node responses.
  - Adapters will later provide registered fixed prefixes; a shared framework mount provides exact root health/status claims. This brief does not choose their route tables or discovery payloads.
  - “Drain” stops acceptance and waits only for transport-active requests/responses. It excludes disconnected and unrelated app-owned durable jobs; a still-active response is forced once the accepted deadline expires.

### DP-24 contract (`decided: DP-24`)

```ts
type MaybePromise<T> = T | Promise<T>;

type HttpMountClaim =
  | { readonly kind: "exact"; readonly path: string }
  | { readonly kind: "prefix"; readonly path: string };

interface HttpMountContext {
  readonly signal: AbortSignal;
}

interface HttpMount {
  readonly claims: readonly HttpMountClaim[];
  handle(request: Request, context: HttpMountContext): MaybePromise<Response>;
}

type HttpListenTarget =
  | { readonly kind: "tcp"; readonly host: string; readonly port: number }
  | { readonly kind: "unix"; readonly path: string };

type HttpBoundAddress =
  | {
      readonly kind: "tcp";
      readonly host: string;
      readonly port: number;
      readonly url: string;
    }
  | { readonly kind: "unix"; readonly path: string };

type HttpListenerState = "running" | "draining" | "forcing" | "closed" | "failed";

interface HttpStopOptions {
  readonly forceAfterMs?: number;
}

interface HttpListenerHandle {
  readonly addresses: readonly HttpBoundAddress[];
  readonly terminal: Promise<void>;
  readonly state: HttpListenerState;
  stop(options?: HttpStopOptions): Promise<void>;
}

function startHttpListener(options: {
  readonly mounts: readonly HttpMount[];
  readonly targets: readonly HttpListenTarget[];
}): Promise<HttpListenerHandle>;
```

**Lifecycle and failure sequence (`decided: DP-24`).**

1. Compile and validate every mount/target first. Reject an empty target list, invalid normalized target, duplicate effective target, malformed path, duplicate claim or overlapping claim without opening an endpoint. `ResolvedHttpServeConfig.targets` supplies the normalized, non-empty plan.
2. Bind serially for deterministic rollback. Every `request` handler waits on the same startup barrier before mounting work. When every endpoint is bound, freeze actual address facts, open the barrier, publish `state = "running"` and return the handle. A queued request never enters an adapter if a later bind fails.
3. On bind failure, reject the startup barrier, close acquired endpoints in reverse order, await every close, clean only identity-proven Unix sockets and reject with the original bind error (not a cleanup error). A pre-existing or never-identified path is never unlinked.
4. Runtime records an active transport request from request acceptance until response completion or disconnect. Disconnect/completion removes it immediately and aborts only for genuine request abort, pre-completion response close, or force. Completed request `close` is not an abort. Late adapter work may settle, but every write is suppressed once removed.
5. First `stop()` atomically changes `running → draining`, closes all endpoints to acceptance and creates the memoized terminal promise. If all active transport work completes and all server/socket cleanup succeeds, transition `draining → closed` and resolve.
6. At 10,000ms by default (or the first call's `forceAfterMs`), transition `draining → forcing`; abort remaining request controllers, cancel readers, destroy remaining Node responses/connections and invoke Node close-all support. After all close/cleanup settles, transition `forcing → closed` and resolve. This force never cancels durable jobs or otherwise waits on/cleans app resources.
7. A second `stop()` during any phase returns the existing promise and ignores later options. `stop()` after close/failure returns that same settled promise. Unexpected server `error` or close outside stop transitions to `failed`, performs best-effort close/owned-socket cleanup and rejects `terminal` with the original runtime error.
8. Private Unix ownership evidence is captured only after a successful `lstat` of the newly bound socket and contains its normalized path plus `dev`/`ino`. Cleanup awaits server close, then `lstat`s the path: unlink only an identity match; `ENOENT` is already clean and a different identity is foreign and preserved. If bind fails or identity was never captured, startup rollback does not unlink that path. TCP cleanup never performs socket-path work.

### Behavior contract

- Input: resolved adapter mount registrations, a normalized bind plan and transport logging/diagnostic context. No CLI argv, raw MCP/REST/RPC envelope or handler declaration enters the listener.
- Dispatch: a request reaches at most one mount. Exact/prefix claims and collisions are settled before binding; method/body/protocol decisions remain inside the selected adapter. Dispatch starts only after every endpoint is ready.
- Request: a native Web `Request` preserves the full URL/method/headers/body stream and gets one fresh `AbortSignal` used by the mount and D2 runner. A genuine abort or pre-completion response disconnect aborts that signal and cancels pending body/response bridge work. A normal completed-body `IncomingMessage` close is not treated as client loss. It does not terminate the dispatcher or another request.
- Response: preserve a handler's native `Response` status, headers and body order. Incremental chunks reach Node without `arrayBuffer()` or full concatenation; `false` writes pause reads until `drain` or close.
- Failure: pre-dispatch/mount exceptions produce a generic 500 with no raw error leakage. Once headers/body have started, terminate the affected stream rather than attempting a JSON replacement. Cleanup must run in `finally` paths and preserve the original bind error for reporting.
- Concurrency: each request owns its controller, stream reader, and Node response. One slow/disconnected stream cannot serialize another request or close the listener.
- Lifecycle: complete startup is all-or-nothing. The handle exposes frozen actual binds, `running | draining | forcing | closed | failed`, and one terminal promise. The memoized `stop()` stops acceptance across all binds, drains only transport-active work, forces after the accepted deadline, releases verified owned endpoints/sockets and settles once. Foreign/pre-existing/replaced paths/resources remain untouched.

### Failure and lifecycle contract

- Bind collision on any target closes all binds acquired earlier in the same attempt in reverse order, rejects the barrier and surfaces the original collision. A Unix path is unlinked only when post-bind `dev`/`ino` evidence matches; a pre-existing, never-identified or replaced path is preserved.
- An unexpected listener exit/error transitions to `failed`, rejects the terminal promise after best-effort cleanup and never becomes an eternal wait or successful exit. First stop resolves once after the selected drain/force cleanup; repeated stop calls return the same promise.
- Client disconnect cancels the response reader and request signal, but another request, dispatcher, listener, MCP task or other app-owned durable job is untouched.
- Startup logging occurs only after every bind succeeds and the startup barrier opens, and uses actual resolved addresses (including ephemeral ports). Stop logging occurs at the accepted requested/final points; the terminal promise settles according to the accepted drain/force semantics.
- `serveHttp` task 20 handoff must remove the one installed signal pair in `finally` and be safe if invoked repeatedly, if bind never completed, or if a socket/path disappeared or was replaced externally.
