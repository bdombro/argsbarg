### Why and canonical context

- Rationale: 8.x derives MCP tools from CLI leaves, reconstructs argv in `src/mcp/tools.ts` / `src/headless/tool-call.ts`, and stores protocol state in `src/mcp/server.ts`. v9 needs one explicit MCP declaration catalog and one native dispatch path shared by stdio, `/mcp`, and local mirror wiring.
- Context: settled seed §§7.6, 7.7, 7.13, 7.16 and 7.19; accepted D2 task 2 and DP-11 task 16; implemented `src/core/invocation.ts` and `src/runtime/invoke.ts`; architecture rev 2 and conventions rev 1.
- Brief mode: full slice. It establishes registry, pure protocol envelopes and call dispatch only; adapters consume it later.

### Observed current and target state

- Current:
  - `collectMcpTools` in `src/mcp/tools.ts` recursively derives tools from CLI commands, sorts by sanitized name, emits object-root schemas, and records `inputWrapped` / `outputWrapped`.
  - `mcpToolCallToArgv` converts arguments to CLI argv; `executeHeadlessToolCall` in `src/headless/tool-call.ts` unwraps input, invokes `App.invoke`, wraps output, and formats failures. This path is incompatible with D2 native binding and must not be copied into v9 dispatch.
  - `handleRequestLine` in `src/mcp/server.ts` owns legacy `initialize`, session protocol selection, roots-era request handling, `tools/list`, `tools/call`, resources, hooks and stdio-oriented control in one function. It is useful protocol/failure prior art only.
  - `src/mcp/result.ts` builds the legacy content/structured-content result envelope. v9 MCP calls have no argv, legacy initialization, roots cwd discovery, or output wrapper.
  - `src/test/integration/mcp.test.ts` proves current framing, validation and concurrency behavior but explicitly treats `2026-07-28` as unsupported. There is no authoritative checked-in 2026 wire fixture for exact `resultType` literals, complete `server/discover` shape, or cache values.
- Target:
  - A registration-time `McpRegistry` contains exactly the tools accepted for exposure. Discovery, listing and call lookup read one immutable snapshot; no entry is reread, filtered or added per request.
  - `protocol.ts` is a pure JSON-RPC/MCP boundary: it decodes unknown envelopes, validates `2026-07-28` request metadata/capabilities, and constructs fixture-pinned protocol results/errors. It imports no registry, adapter, I/O, source, caller, `Response`, or `BoundDeclaration`.
  - `registry.ts` owns unique names, immutable wire views, deterministic ordering and exact lookup. It neither parses requests nor runs guards/handlers.
  - `dispatcher.ts` is stateless method routing. It accepts a decoded request, the registry and adapter-supplied `InvocationBase<Seed>`, looks up once, calls `invokeBound` once, and returns protocol data. It owns no I/O, session/capability state, caller verification or transport status.
  - Every handler gets D2-validated `ctx.inputs`, fresh ordered `ctx.locals`, the adapter signal, `surface: "mcp"`, and exactly one source: local `env` for stdio/mirror or HTTP `headers`. A required caller is an app-typed seed local established by middleware/factory/local binding; D2 does not define a universal top-level caller.
  - Protocol/lookup/Zod failures settle before a handler. Guard denial and exact thrown values remain D2 outcomes until MCP-native encoding. Per-call locals, source, caller, signal and captured output never leak into another call.
  - Every 2026 result carries `resultType: "complete"` in this slice. `server/discover` and `tools/list` carry `{ ttlMs: 3600000, cacheScope: "public" }`; `tools/call` carries neither cache field. The encoder owns these protocol/result fields, not registry annotations or tool declarations.
  - Calls overlap; the accepted scope still forbids `process.chdir` during overlap and passes cancellation only through the call-local signal.
- Non-goals: stdio framing/read loops/write queues; Streamable HTTP listener, `Mcp-Method`/`Mcp-Name` parsing, middleware/OAuth/SSE/status/abort; Tasks provider/protocol/subscriptions; gateway federation; child mounts; CLI mirror/relay; legacy initialization, ping, roots, resources/resource-read tool; public factory/root export; docs/changelog; real host or header claims.

### Decisions and alternatives

- Established:
  - MCP `2026-07-28` only; reject unsupported/missing versions clearly, with the settled `-32022` direction. No initialization or session negotiation.
  - One fixed tool registry serves both transports in separate processes. Discovery and dispatch cannot drift through a second catalog or per-call reflection.
  - D2 owns validation, guard order/locals, cancellation checkpoints and terminal outcomes. The MCP binder supplies native `rawInputs` and `InvocationBase`; adapters encode transport responses.
  - `server/discover`, deterministic `tools/list` and `tools/call` are protocol-owned. Mount middleware, HTTP headers/status/streaming and stdio framing remain adapter-owned.
  - `decided: DP-23`: cacheable `server/discover` and `tools/list` results include exactly `{ ttlMs: 3600000, cacheScope: "public" }`; every result includes `resultType: "complete"` and result `_meta["io.modelcontextprotocol/serverInfo"]`. `tools/call` is not cacheable. Real host behavior remains unverified.
- Proposed:
  - Add internal `src/mcp/registry.ts`, `src/mcp/protocol.ts` and `src/mcp/dispatcher.ts`; keep them package-internal until the factory/public API owner wires declarations.
  - `registry.ts` accepts explicit package-internal entries from the declaration owner, each retaining its concrete `BoundDeclaration`, emitted object-root wire schema and wrapper metadata. Any heterogeneous generic erasure must stay behind a narrow type-safe internal closure; never widen to `any`, infer from `AppSpec`, or rerun CLI conversion.
  - `protocol.ts` owns unknown-envelope decoding, JSON-RPC ID/notification shape, request/result discriminants, `_meta` version/capability validation, cache metadata and protocol errors. `dispatcher.ts` owns method routing, wrapper unbinding and `invokeBound`.
  - Treat `src/mcp/tools.ts` as 8.x prior art, not a target registry. Task 23 does not edit, extend, or preserve a second catalog there. A later integration owner may retain pure reusable wrapping/size helpers while migrating legacy importers.
- Alternatives:
  - Reuse `handleRequestLine` as the core was rejected because it mixes framing, session and legacy behavior with dispatch.
  - Convert MCP to argv was rejected by D2 and seed §7.16.
  - Per-adapter registries would let stdio and HTTP discovery drift; rejected by §7.7.
  - Put Tasks, OAuth or gateway lookup in the dispatcher; rejected because those owners are separate and would couple auth/task lifecycle to basic tool dispatch.
- Assumptions:
  - The declaration/factory task supplies already Zod-typed bound tools. If not, return a focused interface conflict rather than reintroducing `AppSpec`/CLI coupling.
  - A fixed catalog is sufficient: startup omissions affect discovery and dispatch together; per-call guards do not mutate visibility.

### Implementation recipe

1. Add `src/mcp/registry.ts`.
   - Define a frozen `McpToolEntry` with unique wire `name`, description, object-root `inputSchema`, optional `outputSchema`, optional annotations, wrapper metadata and its `BoundDeclaration`.
   - Build one registry from an explicit startup array. Reject empty/duplicate names; sort with a locale-independent code-point comparator; deeply freeze retained wire views so caller mutation cannot change discovery/list/dispatch. Do not infer schemas from CLI commands or rebuild Zod/JSON Schema per request.
   - Expose only immutable discovery/list views and exact lookup. No registration mutation, caller filtering, lazy upstream reflection, credential input or guard execution.
   - Keep `resultType`, `ttlMs` and `cacheScope` out of arbitrary tool annotations. Attach them only at fixture-required protocol result positions.
2. Add `src/mcp/protocol.ts`.
   - Pin `MCP_PROTOCOL_VERSION = "2026-07-28"` and strict decoded types for JSON-RPC requests/notifications, request `_meta`, client capabilities, results, cache metadata and protocol errors.
   - Require params `_meta["io.modelcontextprotocol/protocolVersion"]` as the pinned version and `_meta["io.modelcontextprotocol/clientCapabilities"]` as an object. Optional `clientInfo` must be an implementation object; optional `progressToken` must be a string or integer. Decode JSON-RPC ID/method/params before registry lookup. `initialize` gets `-32022` with `data.supported`; otherwise missing/malformed metadata is `-32602`, unsupported version is `-32022` with `{ supported, requested }`, and malformed envelope/id is `-32600` before method dispatch. String/integer IDs survive unchanged; notifications produce no response and never invoke a tool.
   - Do not interpret `Mcp-Method`/`Mcp-Name`, read stdin/headers/env, or create a `Response`.
   - `decided: DP-23`: encode `complete` results with server identity in result `_meta`; stamp only discover/list as the one-hour/public `CacheableResult`. The exact accepted and negative fixtures live in task 33 and are now implementation inputs.
3. Add `src/mcp/dispatcher.ts`.
   - Accept a decoded `McpRequest`, adapter `InvocationBase<SeedLocals>` and registry. Return a transport-neutral protocol envelope or no envelope for a notification.
   - Build `server/discover` from fixed server/capability construction plus the same registry; build `tools/list` only from registry order. Reject cursors the server did not issue.
   - For `tools/call`, require a string `name`; omitted `arguments` becomes `{}` while supplied arguments must be an object (not null/array/scalar). Reject an unknown name or an unissued cursor before invocation, unwrap only a declared MCP object-root marker, perform exact lookup, then call `invokeBound` once with `{ declaration, rawInputs, base }`.
   - Encode `ok` with the accepted 2026 shape and no legacy `result` output wrapper. Encode `invalid`, denial and thrown `AppError`/unexpected values as MCP-native failures; preserve stable domain fields, avoid stack/raw-credential disclosure, and turn result serialization failures into tool failures before escape.
   - Leave progress/cancellation notifications, access hooks and lifecycle cleanup to adapters. Never mutate/reuse `base`, serialize calls, or issue transport status/streams.
4. Add focused tests:
   - `src/mcp/registry.test.ts`: duplicate/empty names; source mutation after registration; stable insertion-independent order; discovery/list/lookup parity; exact omission; no mutable caller view.
   - `src/mcp/protocol.test.ts`: malformed JSON-RPC/envelope/ID/_meta/params, unsupported/missing revisions/capabilities, `initialize`, cursor and notification cases. Execute every accepted and negative DP-23 vector, including result literals, cache fields and `serverInfo` placement.
   - `src/mcp/dispatcher.test.ts`: catalog parity, unknown method/tool, argument shape/wrapper stripping, no argv/headless dependency, lookup-before-invoke, validation → guards → handler, denial/invalid/exact-thrown/`AppError`/serialization failures, and two overlapping calls with distinct sources, caller locals, signals and output. Verify `process.chdir` remains forbidden and notifications produce no envelope.
   - Do not edit `src/mcp/tools.test.ts`; its legacy argv assertions move/delete only under integration ownership. Reuse only small fixture helpers from existing source tests; do not couple production behavior to a test module.
5. Adapter handoffs:
   - **stdio owner:** owns frame reading, IDs/cancellation/progress controls, raw stdout and process lifetime. It parses one envelope, creates `InvocationBase` with `source: "local"`, fresh signal and stdio/mount seed locals, calls the dispatcher, and writes its response through the raw writer. It never rebuilds or queries another catalog.
   - **HTTP owner:** owns `Mcp-Method` / `Mcp-Name` inspection, `/mcp` middleware/OAuth, HTTP status/headers/stream start, disconnect cancellation and concurrency. Before streaming, it establishes `source: "http"`, a name-only `headers` view and fresh verified/caller seed locals; passes decoded protocol data plus an adapter signal; and encodes only protocol output. Missing/malformed headers never fall back to env, and guard denial settles before SSE starts.
   - **local MCP mirror owner:** constructs local context with the same registry entry and `invokeBound` path, opens no listener, uses no HTTP middleware, and fabricates no headers. Relay is a later native request, not dispatcher substitution.
   - **Tasks owner:** does not patch task methods into task 23. It later adds provider dispatch against the same caller-base/guard composition under its own accepted protocol packet.
6. Finish with the owned validation below and record exact exit evidence. No real host, network, OAuth, or Tasks checks.
