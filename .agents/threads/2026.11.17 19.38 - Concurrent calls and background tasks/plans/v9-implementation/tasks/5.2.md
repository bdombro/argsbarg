# 5.2. Verify app key boundaries

## Notes

- Existing guarantee: `CommandBase.key` is required but typed only as `string` (`src/core/types.ts:408-410`); `AppSpec` inherits it (`:603-607`). `cliValidateProgram` does not check the root app key at all (`src/core/validate.ts:67-121`). `walkNode` only gives keys contextual meaning such as reserved/duplicate child names and parameter-group syntax (`:231-353`). There is therefore no runtime non-empty, single-segment, character-set, or traversal guarantee for an app key in these three files.
- `create` adds no reusable app-key rule. `resolveCreateOptions` accepts the merged key as-is (`src/cli-tool/create.ts:201-221`). `classNameFromKey` is the only incidental restriction: it rejects `""` and strings made only of `-`/`_` while deriving a Ruby class name (`:126-142`); it still accepts path punctuation because it does not validate the original key. Template substitution then writes that key into content and selected relative paths. The existing release-repo pattern is for `org/repo`, not an app-key pattern.
- Proposed rule, `^[A-Za-z0-9][A-Za-z0-9._-]*$`: it guarantees a non-empty, separator-free, single ASCII token beginning alnum. It blocks `/`, `\`, and leading `.`/`-`/`_`, so common directory traversal and cross-segment forms cannot be expressed. It does **not** reject only traversal/path-boundary cases: it also rejects benign keys containing spaces, Unicode, `@`, `+`, `:`, or other punctuation. Conversely, it permits trailing dots and strings such as `a..`; add separate OS/filesystem normalization and reserved-name checks if that risk matters. No existing app-key pattern was found to reuse.
- Examples: pass `myapp`, `App2`, `0-key`, `com.example.app`, `a_b-c`; reject `""`, `.`, `..`, `.hidden`, `-app`, `_app`, `../app`, `a/b`, `a\b`, `app name`, `app:prod`, `café`. `a..` matches the regex but may still need an OS-specific trailing-dot policy.
- Instruction sources explicitly loaded: swarm `common.md`, repository `AGENTS.md` and `README.md`, plan `rules.md`, `architecture.md` rev 2, `conventions.md` rev 1, and repository `docs/*`. There is no `roles/helper.md` in the role directory, so that role-specific playbook is unverified.
