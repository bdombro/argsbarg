### Decider outcome

- **Public API:** `method<Locals>()({ ... })` is the sole declaration identity builder; `name`, `description`, `inputSchema`, and `handler` are required, while `summary`, `outputSchema`, `paramNames`, and operation `guard` are optional. The `jsonRpc: { methods, guard? }` block enables by presence and has no `enabled` flag. Names are exact/case-sensitive, trimmed/non-empty/no-control, `rpc.` is reserved, and duplicates fail registration.
- **Wire:** accept omitted params as `undefined`, otherwise only object/array. IDs are finite `string | number | null`; `0`, `""`, `null`, and fractional numbers are requests, while omitted IDs are notifications. Unknown envelope fields are invalid; duplicate valid batch IDs invalidate each duplicated member without affecting unique members.
- **Errors/safety:** standard codes `-32700/-32600/-32601/-32602/-32603`; denial is `-32001`; `AppError` is `-32000` with only stable code and JSON-safe details. Zod data contains bounded path-prefixed strings. Unexpected errors are generic. Results/error data use strict JSON-value checks; output schemas type/discover but do not run at invocation.
- **OpenRPC:** emit `1.3.2` in catalog order. Strict object input roots become by-name descriptors; fixed tuple input roots become by-position descriptors and require matching unique `paramNames`. Loose/unbounded/non-object/union input or recursive/unresolved/external-ref shapes fail registration. JSON-representable scalar/array/union outputs remain directly represented. Acyclic local refs are inlined; MCP wrapping is excluded.
- **Notifications:** valid notifications execute fully and never emit an envelope. Their bounded outcomes are observer/log-only; single/all-notification HTTP bodies are `204`, while mixed response-bearing batches are `200`. A failed notification cannot rewrite a sibling.
- **Rationale/rejections:** preserve JSON-RPC structured params and standard null/fractional IDs, but reject duplicate IDs and permissive envelope extras because response correlation and typo visibility are safer. Separate custom codes preserve D2 denial/app categories without leaking internals. No runtime output parse avoids changing D2; strict JSON encoding remains mandatory. Unrepresentable OpenRPC shapes fail instead of inventing MCP wrappers or lossy roots.
- **Graph/owner impact:** task 22's focused leaf is no longer blocked by DP-22. Public factory/root export, listener/status implementation, CLI mirror and relay remain named handoffs. No graph split, permission, task owner or dependency change is proposed.
