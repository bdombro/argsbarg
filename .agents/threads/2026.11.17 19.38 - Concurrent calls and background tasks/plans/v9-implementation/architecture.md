# v9 architecture

This is the worker contract for the firm design selected by the user. The [seed](../2026.11.18%20-%20Argsbarg%20next%20major%20design%20decisions.md) stays unchanged as a design reference; examples and alternatives there are not prescriptions. [Workspace baseline](../../workspace.md) identifies 8.x code to inspect or reuse. Seed section numbers below are an absorption index, not implementation tasks.

## Settled contract

| Seed | Binding behavior |
| --- | --- |
| 7.1, 7.16 — Factory, binding and invocation | Keep `argsbarg(spec)` and `app.run()` (Approach C); optional, independent `cli`, `http`, `jsonRpc`, `mcp` blocks; no dummy CLI or required operation layer. Surface adapters bind native inputs, a shared runner validates/guards/invokes, adapters encode native results and errors. No fake argv or headers. D2 fixes the internal boundary: `src/core/invocation.ts` owns source/context/denial/outcome types; `src/runtime/invoke.ts` owns `invokeBound` and compiled guard orchestration; adapters own native binding/encoding. REST merges separately declared path/query/body into typed flat `ctx.inputs`; reject colliding keys when registering, not by precedence. Handlers can return Web `Response` for REST native outcomes, including streams; `AppError` is the one domain-error class. |
| 7.1 — Context and guards | Local (CLI, local mirrors, stdio) reads env only; HTTP reads request headers only, case-insensitively. App startup settings are separate. D2 fixes guard locals as a fresh, ordered per-call object: transport/mount first, then surface default, then operation supplement or explicit override/public replacement. Guards run before side effects and return boolean, typed allow-locals or structured denial; `InvocationOutcome` separately carries denial, invalid input and unknown error with captured output. Required caller must be established on every enabled entry path, including fresh task follow-ups. ALS isolates output/progress/cancellation and does not hide handler data. No raw credential logging or serialization. |
| 7.3 — CLI mirrors | Generate in-process `api` (method, exact full path), `rpc` (method), and `mcp call` (tool) mirrors; same declaration, validation and operation guards, local context, no listener or HTTP middleware. `--relay <url>` makes a true native request to the running server (MCP uses `tools/call` on `/mcp`); no implicit env-to-header forwarding or fallback to local work on failure. |
| 7.4 — Streaming/concurrency | Async calls overlap by default, including on one MCP connection. Isolate caller, captured output, progress and cancellation; preserve wire framing without serializing handler execution. Preserve the `process.chdir` restriction during overlap. Stream with backpressure and disconnect handling without whole-body buffering, including in the REST mirror. Disconnect ends the response, not durable work. No WS or streaming uploads. |
| 7.5, 7.6 — Surfaces and discovery | REST under `/api` with `/api/openapi.json` and `/api/docs`; shared health endpoints and `/status` at root. Standalone JSON-RPC 2.0 at `/rpc` with `/rpc/openrpc.json`, IDs, notifications and independently validated/authorized batch members (not atomic). MCP has `server/discover` and `tools/list`. Dispatch and discovery use the same fixed registered declarations. No inferred `/api-rpc`, `/tools/{name}`, `/tools/openapi.json`, `/mcp-rpc` or MCP OpenRPC. |
| 7.7, 7.13, 7.19 — MCP | One tool registry and dispatcher, separate internal stdio and Streamable HTTP `/mcp` adapters, one selected MCP transport per process. Stdio opens no listener and writes only protocol data to stdout. Only `2026-07-28`: stateless discovery, per-request version/capabilities, `resultType`, required `ttlMs`/`cacheScope` for cacheable results, deterministic listing, standard `Mcp-Method`/`Mcp-Name` HTTP headers; reject unsupported versions clearly. No legacy `initialize`, roots-based cwd discovery, or output wrapper. Mount-local HTTP middleware may deny before dispatch or pass a verified caller. It does not apply to stdio, local mirrors or sibling mounts. |
| 7.8, 7.9, 7.20 — MCP Tasks | Plugin owns capability negotiation, wire validation, explicit task references and named `get`, `update`, `cancel` follow-ups; app supplies caller-aware callbacks and owns job execution/storage, ownership checks and admin/reporting. No capability without a provider; client opt-in required; unsupported clients get inline result or clear error before task-only work starts. `get` includes terminal result/error, `update` answers pending task input; no built-in list/result, queue, auto-promotion, persistence, scheduler, retries, SQL endpoint or dashboard. Fresh caller on each request; request abort is not job cancellation. |
| 7.10, 7.11, 7.12 — Packaging/lifecycle | One repo/package/public root import/release line and one executable per app, Zod-native with no production deps. Import/help don't start resources. `serve` selects service mode; MCP stdio bundle/manifest launches the same executable with `serve mcp --stdio`. Reject combined MCP launch before binding; HTTP shares one dispatcher. Resolve bind config only in HTTP mode; detect collisions, roll back partial binds and drain on shutdown; only remove a socket owned by this runtime. `app.run()` resolves normally so user cleanup runs; never closes borrowed app dependencies. Breaking major: no 8.x shims, aliases, legacy bundles, migration tool or guide. |
| 7.22, 7.11 — Children and gateways | Build-time keyed children in one executable, namespaced declarations and scoped env/header views with no cross-child or unprefixed fallback; reject collisions, preserve child guards and transport exposure. Parent owns transports, not running child app lifecycle. Remove runtime gateway bundle loader and global registry. Curated gateways explicitly register Zod contracts and app-owned upstream clients; no external schema import, live or per-caller catalog, transparent federation, or automatic merge of child OAuth/stores/lifecycle. Omissions at startup affect dispatch and discovery together; per-call guards do not change discovery. |
| 7.21, 7.24 — Auth boundaries | Opt-in `/mcp` OAuth resource-server helper serves metadata and native challenges, with app-owned token verification and policy. Guard denials must be available before SSE starts; distinguish missing/invalid credentials, insufficient scope and non-auth app denial. Verified identity is request-local, not forwarded upstream. Upstream sign-in is separate and app-owned: prefer URL-mode elicitation with a new invocation when supported, otherwise manual connect/rerun; never auto-fallback on decline or change tool schemas. Reauthorize and validate caller-bound continuation/grant on retry. |
| 7.23, 7.25 — App authoring/config | Repo bootstrap skill for new apps and shared intent-first upsert skill for existing apps/templates; `create` remains deterministic scaffolding. Establish intent first, preserve unrelated surfaces, avoid duplicate changes. Config helper is opt-in: explicit absolute override wins or use XDG/macOS/Roaming AppData per-user default; reject bad override, create recursively only when called, no existence probe or workspace/install fallback. App owns settings, storage and invocation of helper. |

## Open technical choices

- Child descriptor, namespace composition/API and typed scoped context; consult the [child preview](../../../../../docs/use-cases/child-apps.md) and [gateway decision note](../2026.11.19%20-%20Gateway%20bundles%20vs%20child%20mounts.md). Guard composition syntax, caller propagation and denial fields: see [guard note](../2026.11.19%20-%20Guard%20composition%20and%20caller%20handoff.md). Settle against local and HTTP paths, including child and task callbacks.
- Listener shape/defaults and app env resolver; `serve` flags, exit-code convention and programmatic running handle; Unix socket support/details and any app-state helper. Listener examples are proposals, not binding APIs. Input, handler, guard, outcome and invoke signatures are settled by D2 above.
- Relay credential/display options, MCP transport middleware and OAuth helper/verifier signatures, typed task callback and reference signatures. Check in-memory and durable task recipes before settling.
- Upstream URL continuation API and first-release eligibility require real harness/upstream evidence that is not authorized here; leave the affected claim unverified. Config-helper signature open. Authoring upgrade-availability checks belong to the future skill behavior; this run makes no external lookups.

Keep the shared semantics small. Resolve choices only where contracts need them and hand accepted decisions to affected branches; illustrative source layouts may change.
