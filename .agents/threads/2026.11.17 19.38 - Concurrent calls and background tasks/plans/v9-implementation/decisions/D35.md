## Decider outcome

### Package-internal registration

Task 36 adds `src/cli/mirror.ts` with the only cross-surface entry/result types:

- `CliCallEntry<Input, Native>` has `invoke(input, context)`, where `input` is
  parsed once by the generated command and is never raw argv.
- `CliCallContext` is discriminated by `mode: "local" | "relay"`. Local includes
  the exact signal, fresh locals and local env `NameView`; relay includes the
  exact signal, validated `URL`, sanitized explicit header entries and injected
  `fetch`. Neither context exposes the other source.
- `CliCallResult<Native>` is one of:
  - `kind: "native"`, `value: Native`, `stdout`, `stderr`;
  - `kind: "failure"`, `category: "input" | "transport"`, safe `code`/`message`,
    optional `status`, `stdout`, `stderr`.
- Register exactly two `CliCallEntry` values per configured surface: `{local,
  relay}`. `native` retains:
  - REST: `Response`, including 4xx/5xx and native streams;
  - RPC: `JsonRpcMethodOutcome`;
  - MCP: `McpResultResponse | McpErrorResponse`.
  A valid remote protocol/application error is `native`, not a transport failure.
  Aborts are transport failures with `code: "CALL_ABORTED"`.

Surface inputs are:

- REST `{ method, fullPath, body? }`; `body` is an optional non-null JSON object.
- RPC `{ method, params? }`; `params` is omitted or an object/array.
- MCP `{ name, arguments }`; arguments are an object, defaulting to `{}`.

Local entries call the accepted catalog/registry and compiled declaration
directly. They must return the native encoding plus the same D2 invocation's
captured output; no second invocation, fabricated `Request`, synthetic headers or
HTTP mount/middleware is allowed. Export only narrow package-internal outcome
encoder helpers from accepted dispatcher modules if needed.

Relay entries perform exactly one fetch. REST uses the relay origin plus the exact
`fullPath`; it does not append `/api`. RPC and MCP POST to the exact endpoint URL.
REST follows no redirect. RPC uses one request envelope with integer id `1`.
MCP uses id `1`, `tools/call`, protocol metadata for `2026-07-28`, and framework-
owned `Mcp-Method: tools/call` / `Mcp-Name`. A relay never performs local lookup
beyond the factory's prevalidated selector, guard execution, discovery, retry or
fallback.

### Generated CLI

- `api <METHOD> <FULL_PATH>`; method is case-insensitive, valid only for the
  registered REST method set, and the full path must be absolute and include all
  query/path text. `GET /api/...` and framework root paths remain exact; no
  hidden prefix.
- `rpc <METHOD>` uses the exact case-sensitive registered method name.
- `mcp call <NAME>` uses the exact case-sensitive registered tool name.
- All three accept repeatable `--header <name:value>` and `--relay <url>`.
  `--header` without `--relay` is a usage error. No token/auth/header-file/netrc/
  proxy flag or environment convention is added.
- JSON is accepted from exactly one optional pipable stdin document. Empty stdin
  means no REST body / omitted RPC params / `{}` MCP arguments. REST rejects
  scalar/null/array bodies. RPC rejects scalar/null/trailing JSON. MCP rejects
  non-object arguments. Malformed or extra JSON is a usage failure before lookup,
  guard or handler side effects.
- A configured but unknown method/tool/path fails as `input` before a local or
  relay invocation. A surface that is not configured contributes no generated
  command; unknown top-level use remains parser help/error.
- `--relay` URLs must be HTTP(S) without userinfo or fragment. REST accepts only
  an origin (no path, query or fragment); RPC/MCP use the supplied endpoint URL.
- Relay headers are explicit argv values only. Names are case-insensitive and
  duplicates are rejected. Reject `host`, `content-length`, `content-type`,
  `connection`, `transfer-encoding` and MCP routing headers; adapters add those.
  Never read process env, prior HTTP request headers, cookies or caller state.

### Result, error, streams and exit policy

The one CLI presenter writes captured stderr to stderr and captured stdout to
stdout before the native value.

- REST streams `Response.body` bytes directly to stdout with backpressure; it
  never buffers, prints a status line or exposes headers. 2xx/3xx exits 0;
  4xx/5xx exits 1. Local stream failure or `CALL_ABORTED` exits 130 if the
  supplied process signal is aborted, otherwise 1.
- RPC success writes one compact JSON result plus newline to stdout. A native
  RPC error writes the safe JSON error object plus newline to stderr.
- MCP tool success writes the complete encoded `result` as compact JSON plus
  newline to stdout. A protocol error or result with `isError: true` writes the
  corresponding native `error`/`result` JSON to stderr.
- `input` and `transport` failures emit only `<CODE>: <safe message>\n` to stderr.
  Remote malformed/non-JSON responses, wrong RPC ID/version, missing MCP envelope
  and RPC/MCP non-2xx status are transport failures with sanitized `status`.
  REST 4xx/5xx remains native. Network, URL and protocol details contain no
  request body, headers, env, cause/stack or credential values.
- Success exits 0; native application/protocol denial/error, input failure and
  transport failure exit 1; caller/process abort exits 130. Explicit help remains 0
  and implicit help remains 1 under DP-20.
